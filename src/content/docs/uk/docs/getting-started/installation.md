OpenFishing працює як один Docker-контейнер на комп'ютері, який належить вам. Ця сторінка
проведе вас від порожньої машини до власного робочого екземпляра. Хочете спершу роздивитися?
[Демо наживо](https://demo.openfishing.org) не потребує ні встановлення, ні реєстрації.

## Перш ніж почати

Вам потрібні:

- **Комп'ютер, що завжди увімкнений**, наприклад NAS, міні-ПК або домашній сервер.
- **Docker із Docker Compose**, встановлений на ньому. На багатьох NAS Docker — це застосунок у
  центрі пакетів; у Linux скористайтеся [інструкцією зі встановлення Docker](https://docs.docker.com/engine/install/). На Synology вона називається Container Manager, на QNAP — Container Station.
- **64-бітний процесор Intel або AMD (amd64).** Образ зібрано лише для amd64, тож машини з
  процесором ARM не можуть його запустити. Щоб перевірити, виконайте на машині `uname -m`:
  `x86_64` означає, що все гаразд; `aarch64` або `armv7l` означає машину на ARM.
  Немає термінала? Подивіться процесор вашої моделі NAS у її специфікаціях.

## Лише спробувати?

Для швидкого знайомства без файлу compose вистачить однієї команди:

```bash
docker run -d -p 3000:3000 \
  -e BASE_URL=http://192.168.1.50:3000 \
  -v openfishing-db:/app/data \
  -v openfishing-uploads:/app/uploads \
  ghcr.io/m1ndgames/openfishing
```

Замініть `192.168.1.50` на адресу вашої машини, щоб посилання й QR-мітки працювали й на інших пристроях.

Так OpenFishing запускається без входу. Коли вирішите залишити його, перейдіть на файл compose:
він тримає ваші налаштування в одному місці.

## 1. Створіть файл compose

Створіть теку `openfishing` і збережіть у ній цей файл:

```yaml title="docker-compose.yml"
services:
  openfishing:
    image: ghcr.io/m1ndgames/openfishing
    container_name: openfishing
    restart: unless-stopped
    ports:
      - "3000:3000"
    volumes:
      - openfishing-db:/app/data
      - openfishing-uploads:/app/uploads
    environment:
      # Адреса, за якою його відкривають
      - BASE_URL=http://192.168.1.50:3000
      # Ваш часовий пояс
      - TZ=Europe/Berlin
      # Вхід: приберіть #, додайте пароль
      # - ADMIN_PASSWORD=

volumes:
  openfishing-db:
  openfishing-uploads:
```

**Змініть ці рядки перед запуском:**

- `BASE_URL`: адреса, яку ви вводите в браузері, з `http://` і портом, наприклад адреса вашого
  NAS. **Вона обов'язкова:** без неї OpenFishing вважає, що працює через HTTPS, і кожне
  збереження завершується помилкою «Cross-site POST form submissions are forbidden». Вона також
  потрапляє в QR-коди, тож використовуйте адресу, за якою машину бачать інші пристрої.
  Закріпіть за машиною постійну адресу в роутері (*резервування DHCP*), інакше вона може
  змінитися, і QR-коди перестануть на неї вказувати.
- `TZ`: ваш [часовий пояс](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones), щоб час уловів не зсувався.
- `ADMIN_PASSWORD`: без нього немає екрана входу, і будь-хто у вашій мережі має повний доступ.
  Приберіть `#` і додайте власний пароль, перш ніж інші люди чи інтернет дістануться до
  застосунку. Ім'я користувача завжди `admin`.

## 2. Запустіть

**Користуєтеся Docker-застосунком на NAS або Portainer?** Створіть новий *stack* (або *проєкт*),
вставте файл вище й розгорніть його.

**Користуєтеся терміналом?** Підключіться до машини (наприклад, через SSH), перейдіть у теку й виконайте:

```bash
docker compose up -d
```

Перший запуск триває хвилину-дві, поки Docker завантажує образ.

## 3. Відкрийте

Відкрийте адресу, яку ви вказали в `BASE_URL`, наприклад **`http://192.168.1.50:3000`**
(або `http://localhost:3000` на самій машині). Ви маєте побачити порожню колекцію приманок,
готову до першої приманки. Якщо ви задали `ADMIN_PASSWORD`, спершу увійдіть як **`admin`**.

Якщо сторінка ще не відкривається, перший запуск може тривати: `docker compose logs openfishing`
показує `Listening on`, коли все готово.

Готово. Далі [додайте першу приманку](/uk/docs/features/lures).

## Де зберігаються ваші дані

- **База SQLite (приманки, місця, улови, спорядження)**: шлях у контейнері `/app/data`, том `openfishing-db`
- **Ваші фото**: шлях у контейнері `/app/uploads`, том `openfishing-uploads`

:::caution
Зберігайте обидва томи. Контейнер, запущений без них, втрачає все після видалення. Для копій
деінде скористайтеся [Резервним копіюванням та відновленням](/uk/docs/backup/backup-restore).
:::

## Оновлення

Спершу зробіть резервну копію (у **Налаштуваннях**, див.
[Резервне копіювання та відновлення](/uk/docs/backup/backup-restore)), потім завантажте новий
образ і перезапустіть:

```bash
docker compose pull
docker compose up -d
```

Міграції бази виконуються автоматично під час запуску, а ваші дані лишаються в томах. У
Docker-застосунку на NAS або в Portainer скористайтеся дією *pull і повторне розгортання* (або
*оновити*) для stack.

Запускали однією командою? Виконайте `docker pull ghcr.io/m1ndgames/openfishing`,
видаліть старий контейнер (`docker rm -f <назва>`) і знову виконайте ту саму команду
`docker run`: іменовані томи зберігають ваші дані.

Хочете самі вирішувати, коли оновлюватися? Замініть образ на тег версії зі
[сторінки релізів](https://github.com/m1ndgames/OpenFishing/releases), наприклад `ghcr.io/m1ndgames/openfishing:<version>`, і змінюйте його, коли
будете готові. Тримайте обидві машини на одній версії, коли переносите копію.

## Reverse proxy і HTTPS

Щоб користуватися OpenFishing поза домом, поставте його за reverse proxy, який обробляє HTTPS, і
задайте `BASE_URL` як публічну адресу. Для Caddy це вся конфігурація:

```text title="Caddyfile"
fishing.example.com {
  reverse_proxy localhost:3000
}
```

У nginx передавайте стандартні заголовки проксі й дозвольте завантаження розміром із фото:

```nginx title="nginx"
location / {
  proxy_pass http://localhost:3000;
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto $scheme;
  client_max_body_size 100m;
}
```

Спершу задайте `ADMIN_PASSWORD`: екземпляр без входу ніколи не повинен бути відкритим в інтернет.
