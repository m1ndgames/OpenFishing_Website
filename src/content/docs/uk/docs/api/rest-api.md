OpenFishing має **JSON API лише для читання**, щоб переносити приманки, місця, улови та
спорядження в інші інструменти: таблицю, домашню панель, скрипт. Змінити через нього нічого не можна.

## Ваш токен

- **Із входом:** кожен обліковий запис має власний токен. Скопіюйте його в **Налаштування → Мій
  обліковий запис → API-токен**. **Перегенерувати токен** створює новий; старий перестає працювати.
- **Без входу** (одна спільна колекція, див. [Багатокористувацький режим і автентифікація](/uk/docs/multi-user/authentication)):
  API теж відкритий і токен не потрібен.

Надсилайте токен у заголовку `Authorization`:

```http
Authorization: Bearer <ваш токен>
```

## Кінцеві точки

Кожен ресурс має список і окремий запис:

- `GET /api/v1/<resource>` повертає список.
- `GET /api/v1/<resource>/{id}` повертає один запис.

Ресурси: `lures`, `spots`, `catches`, `rods`, `reels`, `lines` і `combos`. Із входом ви
отримуєте лише дані власного облікового запису.

## Спробувати в браузері

- **`/api-docs`** на вашому екземплярі відкриває інтерфейс Swagger, де можна спробувати кожну кінцеву точку.
- **`/api/openapi`** віддає специфікацію OpenAPI для інструментів, що генерують клієнти.

## Приклад

```bash
curl -H "Authorization: Bearer $OPENFISHING_TOKEN" \
  http://192.168.1.50:3000/api/v1/lures
```

Відповідь у форматі JSON. Кожна приманка має всі свої поля; тут скорочено:

```json
[
  {
    "id": "6f1c2b7e-3d4a-4b8e-9f21-0a5c7d9e1b34",
    "lureNumber": 1,
    "name": "Perch shad",
    "brand": "Example",
    "color": "Perch",
    "favourite": true,
    "lost": false,
    "tags": ["perch", "river"]
  }
]
```
